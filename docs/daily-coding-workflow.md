# Weftara daily coding workflow

Weftara is the primary product name. The existing repository URL, internal binary names, application identifier and `~/.spatial-constellation` state location remain compatible. This is a development application, not a signed distribution. The preliminary brand screen is not trademark or domain clearance.

## Workflow

1. Choose **New session**, enter a Git repository root and a task. **Create an isolated task worktree** is selected by default. This creates `weftara/<session-id>` from committed HEAD under the private supervisor state's `worktrees` directory. Uncommitted source-checkout changes are not copied. Uncheck isolation to use the existing checkout directly.
2. Muse runs through the existing approvals, questions, steering and cancellation controls. Its host remains independent of the window lifetime.
3. Open the inspector's **Workspace** tab. Filter Git-visible file paths, inspect a text file and add its contents to the task draft. Inspect the draft before sending it. Ignored files are excluded; binary files and files above 64 KiB cannot be attached this way. Drafts retain their existing in-window lifetime; they are not durable across app restarts.
4. Use **Refresh change preview** for tracked changes and new files. This preview has a content identity independent of staging. Existing immutable diff captures and human evidence retain their original separate identity and provenance model.
5. Enter a test command and choose **Run command**. It runs under the developer's macOS account, outside Muse's sandbox, in this session's checkout. This is a bounded non-interactive shell runner, not a PTY terminal. No stdin is available. The default deadline is 120 seconds, with 64 KiB of output per stream. Output streams into the local journal. Exit status and content fingerprints before and after execution are recorded as `developerExecuted`, not as a human attestation or automatic acceptance. The public API optionally accepts an integer `timeoutSeconds` in 1..120. Tests may modify files or have external effects; equal endpoint fingerprints do not prove a hermetic environment or rule out transient edits.
6. In an idle isolated task, choose **Commit changes**, inspect the preview and enter a message. This stages all Git-visible changes and commits on the task branch. It does not push or modify the source checkout. Git hooks and commit signing are disabled for these bounded operations; use an external Git client when your project requires them. Identity comes from normal Git configuration. Failed commits can leave the index staged and remain visible in the journal.
7. **Archive session** stops the Muse context and frees an active-session slot, retaining the worktree, branch, local transcript window, artifacts and evidence. Archived sessions are read-only and excluded from attention. Use **Show archived sessions** to browse them. Native Muse history stays in its durable store; the archived UI retains its existing last-100-item snapshot, not a newly copied full-history archive. Start a new session against the retained worktree to continue coding.
8. **Discard worktree** requires a fresh preview and typing the complete session ID. It archives the session and removes its managed worktree, including uncommitted and ignored files. The original checkout and committed task branch remain. A removal failure leaves the archived session and command error visible; a retained worktree can be previewed and discarded again with a new request ID. No source checkout can be discarded through this operation.

## Invariants and limits

- The Rust supervisor owns workspace operations and stable command journaling. React receives no generic process-spawn capability. Explicit developer test commands are the deliberate code-execution boundary.
- Mutations require a current idle Muse session and no running developer test command. Archiving an unavailable session remains possible because it stops the host and retains files. Archived cleanup is separately permitted.
- Start intent is persisted before creating a worktree. A repeated request ID returns the recorded outcome, including uncertainty, rather than creating another branch or worktree. Filesystem/Git and SQLite effects are not one atomic transaction. Failed startup leaves its planned workspace identity visible for inspection; resources are retained rather than silently deleted.
- Commit and discard recheck the current preview. The supervisor serializes harness commands; it cannot lock out editors or external processes. Fingerprints detect observed changes, not an atomic filesystem snapshot. The commit path checks again after staging.
- A normal supervisor shutdown kills test process groups, including descendants. Deadlines and output-budget failures also terminate the group. Abrupt host loss can leave an uncertain external effect; on restart a previously running test becomes `outcomeUnknown` and is never rerun automatically. Output and commands may contain sensitive repository material and remain private local data.
- There are ten active sessions and at most 100 retained session records. The command journal remains capped at 2,000 records and status presents its latest 100. Existing artifact, file and output budgets still apply. Archive is retention, not an unlimited storage or garbage-collection facility.
- Muse can omit resumable history for an empty session with no turns; a native `sessionNotFound` recovery failure stays visible. The desktop requires an initial task. Failed or unavailable sessions can be archived without deleting their worktree or local journal.
- Journal schema 3 preserves existing data and prevents older schema-2 binaries from reopening archived sessions accidentally. Downgrade is refused. Back up the state directory while the supervisor is stopped before testing older builds.
- Muse and the official SDK are now pinned to 1.4.9 after the installed Muse binary advanced. Exact binary version and schema checks remain enforced. Historical Stage A/B/C measurements retain the version on which they were recorded.

## Acceptance and remaining product work

The lifecycle test drives the public API through a real Muse host with a scripted loopback provider: isolated start, a permission-gated file implementation, direct passing tests, time/output failures, stale-preview rejection, idempotent commit, worktree removal with branch retention, and archive across supervisor restart. The browser workflow uses React and the native Rust bridge; native WebView and paid-provider checks are recorded separately when completed.

This milestone does not add Git push/PR/merge/conflict resolution, selected-hunk staging, an embedded editor or PTY, desktop notifications, usage budgets, global transcript search/export, a dependency scheduler, or automatic evidence acceptance. Those remain product work; no SDK capability alone counts as a delivered UI feature.
