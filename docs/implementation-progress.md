### Full data disk (R7, 21 October)

A probe with Lascoria's state folder on an 8 MB tmpfs (Linux, real Muse, controlled model with a 1.5-second reply) found that a disk filling while Muse worked stopped every Muse host: the first refused snapshot write ended the broker, the interruption could not be written either, and the session stayed "connected" with its task never finishing. After space was freed the next task was reported as an unknown outcome and the earlier one as cancelled. New requests were refused with SQLite's "database or disk is full".

`supervisor/src/unsaved.rs` now keeps, per session host, the newest state snapshot and every fact that marks a command applied (at most 2,000) when the database refuses a write, and writes them as soon as it can: after the next update and once a second. Interruptions are kept the same way. Status reports `storage` (count, plain message, since) and is never answered as "unchanged" while anything waits; the app shows "Changes not saved" with the reason. Storage errors returned to the app are reworded ("…the disk is full. Free some space, then check the session before trying again."). The retry buffer is in memory: if the background service stops before storage recovers, its unsaved projection/receipts may be lost and command outcomes can remain uncertain. Muse history is not a substitute for the supervisor journal; the app warns users to keep Lascoria running until the notice clears.

Evidence: `test/storage-full.test.js` (Linux as root, otherwise skipped) fills the disk during a task, sees the warning with the host still connected and a new task refused, frees space, and sees the finished task saved by itself and the refused request accepted with its original identity; the same probe on the previous supervisor reproduced the stuck session. Unit tests in `unsaved.rs` cover deferral, both commands applied after the flush, deferred interruptions and the wording; `test/ui/storage.spec.ts` covers the banner appearing and clearing.

### Damaged data file and startup failures (R7, 21 October)
