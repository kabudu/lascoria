### R3 in-app updates and the release pipeline (18 October)

Updates: the official Tauri updater plugin (2.13.1) is driven by Rust commands only; its own IPC commands are not granted to the WebView. Release builds bake in the maintainer's public key and require the signature's signed version to match the announced one, so a crafted manifest cannot downgrade to an older signed build; development builds report updates as not configured. **Settings, Updates** shows the installed version, last check, available version and notes, checks on request (one at a time, 30-second timeout) and automatically once a day unless turned off, backing off six hours after a failure; a found update only adds a small **Update available** toolbar button. Download (with progress and cancel) and **Install and restart** are separate steps, and installing asks first. On Windows, where the installer must replace the running background service, installing pauses work first; on macOS and Linux running work continues, and the new app shows a banner while the background service is an older version: **Restart background service** when idle, or **Restart when work finishes** / **Pause work and restart now** while tasks run. The supervisor now reports `appVersion` for this handoff. Stable and beta channels are separate; beta never applies unless chosen.

Release pipeline: `.github/workflows/release.yml` (inactive while private) follows qatq: tag on the default branch, `scripts/release.js verify` checks every version field, the CHANGELOG section and the curated `docs/releases/vX.Y.Z.md`; native builds for macOS arm64/x64 (signed, hardened runtime, bundled Node with JIT entitlements, notarized), Windows x64 NSIS and Linux x64/arm64 AppImage and .deb; `scripts/release-artifacts.js` gives every package a collision-free name, writes the signed `latest.json` and `SHA256SUMS.txt`; publishing goes through a draft whose asset list is checked before it is made public, and a published release is never overwritten. `scripts/release.js prepare` manages the CHANGELOG and version bumps. Action references are pinned to commit SHAs; `actionlint` passes. Process and secrets: [Cutting a release](RELEASE.md#cutting-a-release).

Tests: `test/release.test.js` (version ordering, CHANGELOG promotion and extraction, curated-note validation, collision-free staging, manifest and missing signatures) and `test/ui/updates.spec.ts` (explicit check, download and confirmed install; pausing before install where required; restart of an older background service only once work finishes). Not yet proven: a real signed update on any OS, which needs the maintainer's key and a published release.
